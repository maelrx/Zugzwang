# Contributing to Zugzwang

Thank you for contributing to an infrastructure project where protocol honesty matters as much as code correctness.

## Before opening a change

- read `START_HERE.md` and `AGENTS.md`;
- search the backlog and ADRs;
- identify requirement and milestone;
- do not implement around a pending human gate;
- open an issue for a new public contract, scientific protocol or large dependency.

## Contributions welcomed

- provider and evaluator adapters with contract fixtures;
- deterministic environments and codecs;
- reproducibility, fault and migration tests;
- experiment designs and contamination controls;
- documentation and primary-source literature updates;
- performance improvements with measurements;
- accessibility and future UI proposals after the trigger.

## Pull requests

Use a focused branch and the PR template. Include commands and evidence. Real-provider costs must be declared. Generated outcomes or raw API responses must follow retention and redistribution policy.

## Research integrity

Do not cherry-pick games, hide retries, mix assistance regimes, remove failures or overstate a result. Negative findings are first-class contributions.

## Developer Certificate / CLA

No DCO/CLA is selected in the foundation pack. Governance will ratify contribution attestation before the first external code release.

## Conduct

Participation is governed by `CODE_OF_CONDUCT.md`.
