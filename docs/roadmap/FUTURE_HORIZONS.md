# Horizontes posteriores ao v0.1

O futuro é organizado por evidence triggers, não por calendário imaginário.

| Horizonte | Trigger mínimo | Possível entrega |
|---|---|---|
| API local | dois consumidores além da CLI | FastAPI adapter sobre application services |
| Web UI | bundle/query APIs estáveis | run lab, trace explorer, comparison dashboard |
| Postgres | writer/host limit medido | repository adapter e remote daemon |
| Object storage | CAS local insuficiente | S3-compatible artifact backend |
| Distributed workers | workloads multi-host comprovados | queue/coordinator or Temporal reassessment |
| RAG | static KnowledgePacket ceiling demonstrado | retrieval protocol K6 with corpus provenance |
| Training | evaluation suite estável | SFT/RLVR adapters as separate packages |
| Other games | chess contracts no longer dominate | environment SDK validated by second domain |
| Hosted product | repeatable user demand | closed control plane preserving open protocol |

Nenhum horizonte invalida a regra: a evidência e o protocolo permanecem portáveis fora do serviço hospedado.
