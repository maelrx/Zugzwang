## Contexto

O CB-WO-02 define a camada de contratos do CognitiveBoard antes de qualquer
implementação de percepção/executor (caminho crítico §38.1). O PRD fornece os
contratos de referência integrais (§42) e a semântica das chaves (§7.2). Os DTOs
seguem o padrão do repo: pydantic v2 estrito (`extra=forbid`, `frozen`), schemas
derivados dos modelos (não editados à mão).

## Non-goals

- Nenhum comportamento de runtime: a factory de sessão (§26.1) é CB-WO-05.
- Nenhum codec textual do PositionPacket (§42.5 integral) — tipo do DTO agora,
  percepção/codec no CB-WO-03.
- Nenhuma migration; nenhum provider real; nenhum comando de CLI novo.

## Delta planejado

1. `domain/cognition.py` — chaves §7.2 como value objects com builders canônicos;
   catálogo de erros §15.1 (código/categoria/política) com `max_protocol_errors`;
   máquina de estados §12.2 (agregados + fases internas + transições legais);
   envelope de tools §42.6; manifest de decisão resolvido com hashes canônicos;
   config delimitada com flags default-off (G-CB-08).
2. `ports/cognition.py` — `StateIdentityPort` e `CognitiveSession` (§11.1) como
   Protocols runtime-checkable, sem imports concretos.
3. `ports/strategy.py` — campo opcional `decision_session` (default None) no
   DecisionContext (§26.1, aditivo).
4. `spec/json_schema.py` — registro dos novos schemas; `uv run zugzwang schema`.
5. `fixtures/contracts/cb/` — exemplos válidos; `tests/contract/test_cb_contracts.py`.
