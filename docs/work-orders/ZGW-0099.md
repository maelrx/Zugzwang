## Contexto

CB-M3 é a terceira migração cognitiva: versões de skill imutáveis com pipeline
CANDIDATE→APPROVED/REJECTED, sets DRAFT→SEALED com membros aprovados, e a
amarração `cb_decisions.skill_set_id` (a coluna já existe no DDL-alvo §43.2;
a CB-M1 intermediária não a criou — esta migração a adiciona). O registry
`SkillRegistry` valida ativação por allowlist: texto de skill nunca vira
capability nem comando.

## Nota de transcrição (triggers de decisão)

O DDL normativo usa `IS NOT` (em SQLite, `NULL IS NOT 'x'` é TRUE — o que
congelaria NULL para sempre e impediria o próprio bind que o §38.13 exige).
Implementado NULL-aware: primeiro bind (NULL→valor, set SEALED verificado
no registry + trigger de insert) permitido; qualquer mudança posterior
aborta. Semântica preservada (identidade imutável após bind), workflow
de bind viabilizado.
