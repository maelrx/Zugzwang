## Problema (evidências do dossiê)

1. **P0.1 — Referências de calls trocadas (§13).** `CognitiveLoop._record_call` grava `attempt_id` sintético
   (`{decision_id}:{ordinal}`), mas `RecordingBackend` indexa a evidência por `att_*` real; o lookup nunca
   bate e o fallback `reversed()` injeta artefatos da rodada errada (2.068/2.273 mismatches).
2. **P0.2 — Provider error vira "lance ilegal" (§9.1).** O loop cognitivo engole exceções de inferência
   (429/timeout/transporte) como protocol error; o trace não carrega veredito `provider_error`; o
   coordenador contama como retry ilegal → E/G/J/L morreram de `illegal_action_retry_exhausted` com
   throttling no trace.
3. **P0.3 — Ablação não exercitada (§5).** `position.ascii` e `history` declarados no manifest nunca chegam
   ao pacote L0 do caminho cognitivo (só FEN + piece map); config não suportada é ignorada em silêncio.
4. **P0.4 — Sem pin por run (§5.4).** Nenhum git SHA/dirty/manifest de exposição por run.
5. **P0.5 — Concorrência descontrolada (§9).** Até 8 requests simultâneos na mesma quota; nenhum
   `Retry-After` honrado; campanha sem semáforo global. **Diretiva do operador: ≤5 partidas simultâneas.**
6. **P0.6 — Contador físico artificialmente zero (§14).** `settle_tool_operation*` nunca persiste
   `physical_rules_queries`/`logical_ops`/`new_nodes` (sempre 0 nas 1.829 operações).
7. **Ordem 4 — Ciclo filho→neto impossível (§6.3).** `board_expand` devolve só referência do filho; o
   orçamento de 4 calls (observe→expand→observe→finalize reservado) fecha antes de qualquer neto.

## Requisitos

- **R1:** Join CallRecord↔evidência por identidade do chamador (`CallContext.attempt_id`), sem fallback
  por ordem; evidência ausente permanece ausente. Regressão: 2 calls com usage/conteúdo distintos → cada
  `CallRecord` aponta para os próprios artefatos (falha no código velho).
- **R2:** Exceção de provider na decisão ⇒ decisão FAILED com classe distinta
  (`provider_throttling`/`provider_transport`/`provider_timeout_unknown`), veredito `provider_error`,
  episódio com outcome `provider_error` + stable_code — nunca contada como retry ilegal.
- **R3:** `position.ascii` e `history {last_n|full}` declarados ⇒ campos efetivamente no pacote L0
  (`representation.ascii`, `history[]`); `image` no caminho cognitivo ⇒ rejeição explícita (fail-closed).
- **R4:** Toda run grava `code_git_sha`, `code_dirty`, `exposure_manifest_artifact_id` (declarado vs
  efetivo vs não-suportado) + resolved manifest (já existente).
- **R5:** `scripts/run_matrix.py` limita a N runs simultâneas (default **5**, diretiva do operador);
  `ProviderThrottlingError` carrega `retry_after` e o retry de throttling honra o intervalo (cap 120s);
  `outcome_unknown` continua sem retry silencioso.
- **R6:** Settlement persiste `physical_rules_queries`, `logical_ops`, `new_nodes` reais.
- **R7:** `board_expand` devolve o pacote L0 de cada filho inline; expandir a partir de filho (neto) é
  possível e demonstrável com backend fake; prompt informa o ciclo candidato→filho→resposta→neto.
- **R8:** `max_rounds` configurável por manifest para `chess.cognitive_navigation`.
