# ZGW-0104 — Provider adapter `provider.zcode_glm` (ZCode Coding Plan / GLM-5.3-Flash)

Data: 2026-09-08 · Operador: Mestre Mael (diretiva de chat: "criar um adaptador tipo o
do gemini antigravity cli só que do zcode rodando glm 5.3 flash pra rodar os runs zug,
teste tudo até conseguir").

## Requisitos

- R1: novo plugin `plugins/provider-zcode-glm` expondo `provider.zcode_glm`
  (entry point `zugzwang.providers`), backend de UMA inferência por chamada —
  nunca agente/política/jogador.
- R2: fala Anthropic-Messages com o mesmo gateway da sessão ZCode do operador
  (`base_url` default `http://127.0.0.1:8787/anthropic`), modelo `GLM-5.3-Flash`.
- R3: credencial por referência `env:` via `resolve_secret`; segredo literal em
  manifesto é proibido; a chave NUNCA vai para artefato de wire.
- R4: evidência completa: `wire_request`/`wire_response` no `ProviderResult`,
  usage com `source=PROVIDER`, `ReasoningTelemetry` com os blocos `thinking`
  expostos pelo GLM (wire fidelity FULL).
- R5: taxonomia fail-closed: 429→`ProviderThrottlingError` (honra Retry-After,
  teto 120s), 5xx/4xx→`ProviderServerError`, timeout→`ProviderTimeoutError`,
  transporte→`ProviderConnectionError`.
- R6: tool loop do modo cognitive (tools canônicas → `tools`/`tool_use`/
  `tool_result` do wire) suportado ponta a ponta.
- R7: controle de raciocínio: `reasoning_effort` mapeado para
  `thinking.budget_tokens` (low=1024, medium=4096, high=8192). Limitação
  registrada: o GLM-5.3-Flash ignora `thinking.disabled` e sempre emite thinking.
- R8: single-flight opcional por flock (`single_flight_lock` no backend_config),
  mesmo padrão ZGW-0103/ZGW-0101.
- R9: testes offline por default (httpx MockTransport); rede só no smoke real
  explicitamente autorizado pelo operador nesta diretiva.

## ADRs aplicáveis

- Segue o padrão de provider plugin existente (openai_compatible/opencode);
  nenhuma mudança de arquitetura → sem ADR novo.
