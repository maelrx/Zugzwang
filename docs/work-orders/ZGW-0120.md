## Context

O gateway Console Go (pool `opencode-go` do router local) expõe `deepseek-v4.1-flash`
(effort low/high/max, tool calling, thinking interleaved). Três correções eram necessárias:

1. **Router local** (`~/.config/opencode/opencode_router.py`): `deepseek-v4.1-flash`
   adicionado a `GO_MODELS` (backup `opencode_router.py.bak-v41-*`; serviço
   `opencode-router.service` reiniciado). `GET /v1/models` passa a listar o modelo.
2. **Adapter openai-compatible (profile responses)**: o upstream exige que todo
   `function_call` no input tenha o `reasoning_text` de origem no thinking mode.
   As chamadas sintéticas do harness (`harness:preload-root`, `harness:preload-expand`)
   não têm reasoning; agora são lowerizadas para mensagens de texto
   (`[harness tool call]`/`[harness tool result]`), preservando function calls reais.
3. **Arena**: provider `opencode-go` adicionado ao registry (factory Responses,
   `http://127.0.0.1:8788/v1`, effort default low) para partidas ao vivo no webapp.

## Non-goals

- Não altera o contrato canônico nem o router de produção além do catálogo Go.
- Não inclui reenvio de reasoning de function calls reais (upstream aceita via sessão).
- Não promove claims de força; runs são exploratórios.

## Invariants at risk

- Wire evidence continua integral; a transformação de harness é determinística e testada.
- Nenhuma chamada paga nova fora do pool já usado; custo segue `unknown` (GATE-009).

## Planned delta

- `adapter.py`: lowering de `harness:*` como texto no profile responses.
- `providers.py`: `_deepseek_factory` + registry `opencode-go`.
- Testes de contrato e de unidade; manifests em `experiments/deepseek-v4-flash/`.
- Router local: uma linha de catálogo (fora do repo).
